# opss — Passenger (Android)

اپلیکیشن اندروید مسافرِ پلتفرم چندسرویسی **opss** (سورس v3Cube، سال ۲۰۲۱).

| مورد | مقدار |
| --- | --- |
| Package | `com.alaadcin.user` |
| minSdk / targetSdk | 17 / 31 |
| Gradle / AGP | 5.4.1 / 3.5.2 |
| JDK در CI | **17 برای sdkmanager** · **11 برای Gradle** |
| Flavor | `prod` |
| Backend | `https://taxi.ecardo.ir/` |
| نسخهٔ منتشرشده | **v0.0.35** |

## وضعیت نسخهٔ منتشرشده

این نسخه روی یک دستگاه مجازی اندروید (API 30) **واقعاً نصب و اجرا شده است**، نه
فقط روی کاغذ تأیید شده:

| بررسی | نتیجه |
| --- | --- |
| `INSTALL` | `ok` — اندروید بسته را پذیرفت |
| `PACKAGE_PRESENT` | `yes` |
| `ALIVE` | `yes` — پروسه بعد از ۴۵ ثانیه زنده است |
| `APP_CRASH` | `no` |
| امضا | v1 (JAR) و v2 (APK Signature Scheme v2) هر دو تأیید شدند |

اسکرین‌شات از برنامهٔ در حال اجرا و کل لاگ، در آرتیفکت
`install-evidence-*` همان اجرای راستی‌آزمایی ذخیره شده‌اند.

## چرا JDK 11 و نه 8

سورس برای JDK 8 نوشته شده بود، ولی annotation processor زبان Kotlin با JDK 8
روی این پروژه می‌شکند (`AssertionError: annotationType(): unrecognized Attribute
name MODULE`). Gradle 5.4.1 هم با JDK 17 سازگار نیست. بنابراین CI از JDK 11
استفاده می‌کند. **هیچ نسخه‌ای از Gradle، AGP، Kotlin یا targetSdk ارتقا نیافته است.**

## قوانین کاری این ریپو

این قوانین برای هر کسی که روی این پروژه کار می‌کند الزامی است:

1. **کار فقط از راه GitHub.** بیلد، تست و انتشار باید روی runner گیت‌هاب انجام
   شود. روی سیستم محلی `gradlew` اجرا نشود.

2. **دیباگ فقط روی شاخهٔ `fix/stable`.** به `main` فقط کدی می‌رسد که روی شاخهٔ
   دیباگ سبز شده. هر push به `main` یک نسخهٔ جدید و یک Release عمومی می‌سازد، پس
   `main` باید همیشه قابل انتشار بماند.

3. **هر push به `main` نسخه را یک پله بالا می‌برد** و `versionCode` یکی اضافه
   می‌کند. نسخه **پیش از بیلد** رزرو می‌شود تا `versionName` و `versionCode`
   داخل APK با تگ Release یکی باشند. تگ همیشه `v<versionName>` است.

4. **نسخه نهایی فقط در Release است.** فایل artifact برای مصرف داخلی و تست
   است؛ چیزی که کاربر دانلود می‌کند از بخش Release می‌آید.

5. **ارتقای ابزار ممنوع است** مگر با تأیید صریح. Gradle، AGP، Kotlin، JDK،
   minSdk و targetSdk دست‌نخورده می‌مانند.

6. **هیچ توکن، کلید یا keystore داخل مخزن نیست.** برای بیلد ساخت، مقادیر
   به‌صورت `****` نشان داده می‌شوند.

7. **هر تغییر، یک کامیت با پیام روشن.** قالب پیام: `fix(دامنه): علت`.

## سه ورک‌فلو، سه کار جدا

| ورک‌فلو | کار | کِی اجرا می‌شود |
| --- | --- | --- |
| `build.yml` | بیلد APK، امضا، بررسی صحت فایل، انتشار Release | هر push به `main` یا `fix/**` |
| `verify-install.yml` | نصب و اجرای واقعی روی شبیه‌ساز، اسکرین‌شات و لاگ | دستی یا تغییر خودش |
| `scan-sources.yml` | پیدا کردن دامنه‌های کهنه و مسیر `BuildConfig` | دستی یا تغییر `app/src` |

جدا بودن راستی‌آزمایی از بیلد عمدی است: شبیه‌ساز به KVM، نمایشگر X و کتابخانه‌های
Qt/GL نیاز دارد که runner بیلد به آن‌ها نیازی ندارد. runnerای که نتواند شبیه‌ساز
بالا بیاورد باید «تأیید نشده» گزارش شود، نه اینکه سبز کاذب بدهد.

### دام‌های شناخته‌شدهٔ ورک‌فلو

اینها همگی روی runner واقعی آزموده شده‌اند و در کد توضیح داده شده‌اند:

- **اکشن شبیه‌ساز `script` را خط‌به‌خط به `/usr/bin/sh` می‌دهد.** یعنی `dash`
  است و `set -o pipefail` ندارد، و یک `while` یا `if` چندخطی به خط اولش بریده
  می‌شود و با خطای نحوی می‌میرد. هر ساختار باید تک‌خطی باشد.
- **هیچ متغیری از یک خط به خط بعد نمی‌رسد.** هر چیزی که خط بعدی لازم دارد باید
  دوباره محاسبه شود یا در فایلی زیر `$GITHUB_WORKSPACE` نوشته و بازخوانی شود.
- **اکشن شبیه‌ساز فایل مرحلهٔ قبل را نمی‌بیند.** مسیر APK به‌صورت بیان `${{ }}`
  خالی می‌رسد، پس اسکریپت خودش آن را از Release عمومی می‌گیرد.
- **`boot_completed=1` یعنی بسته‌بندی آماده است، نه بستن کامل دستگاه.** نصب در
  آن پنجره خطای خالی می‌دهد که با بستهٔ ردشده اشتباه گرفته می‌شود، پس اسکریپت
  صبر می‌کند.
- **ایمیجر یک برنامهٔ Qt است و به نمایشگر نیاز دارد.** تصویر runner کتابخانه‌های
  Qt/GL/X11 را ندارد و خودش هم `DISPLAY` را درست به پروسه نمی‌رساند.

## نصب روی گوشی

بیلدهای فعلی **debug** هستند و با کلید استاندارد debug اندروید امضا شده‌اند.

اگر قبلاً نسخهٔ اصلی فروشنده روی گوشی نصب بوده، **اول باید آن را حذف کنید**.
اندروید اجازه نمی‌دهد اپی با امضای متفاوت روی اپ دیگری نصب شود و پیام
`there was a problem while parsing the package` یا
`App not installed` می‌دهد.

بیلد بدون امضا اصلاً ساخته نمی‌شود: مرحلهٔ بیلد فایل را با `apksigner`
بررسی می‌کند و اگر امضا درست نباشد بیلد شکست می‌خورد.

## آدرس بک‌اند

آدرس سرور یک جا تعریف شده و از خط فرمان قابل تغییر است:

```bash
./gradlew assembleProdDebug -PSERVER_BASE_URL=https://example.com/
```

مقدار پیش‌فرض `https://taxi.ecardo.ir/` است و در `BuildConfig.SERVER_BASE_URL`
قرار می‌گیرد. کلاس `CommonUtilities.SERVER` همین مقدار را می‌خواند، پس همهٔ
URLهای برنامه از یک نقطه می‌آیند.

## فارسی و راست‌چین

`app/src/main/res/values-fa/strings.xml` وجود دارد و `android:supportsRtl="true"`
در مانیفست فعال است. ترجمهٔ کامل رشته‌ها هنوز انجام نشده؛ رشته‌های ترجمه‌نشده به
زبان پیش‌فرض برمی‌گردند تا متن شکسته نمایش داده نشود.

## کاهش حجم APK

- `abiFilters 'armeabi-v7a', 'arm64-v8a'` — معماری‌هایی که هیچ گوشی واقعی از آن‌ها
  استفاده نمی‌کند حذف می‌شوند.
- نتیجه: حجم APK از حدود ۵۵MB به حدود ۴۳MB کاهش یافته است.

## نکات فنی مهم

- **`jcenter()`** تعطیل شده و با `mavenCentral()` به‌همراه آینهٔ
  `maven.aliyun.com/repository/jcenter` جایگزین شده است.
- **NDK 22** باید نصب باشد؛ فایل‌های `.so` پیش‌ساخته با همان نسخه ساخته شده‌اند.
- **امضای release** به keystore فروشنده اشاره می‌کند که در این ریپو نیست؛
  به همین دلیل شرطی است و در نبود آن از کلید debug استفاده می‌شود.

### okhttp: یک تداخل که دو شکل داشت

`app/libs/projectlibfile.aar` کتابخانهٔ **okhttp 3.8.1** را داخل
`classes.jar` خودش دارد (نسخه از `okhttp3.internal.Version` تأیید شد). چون aar
از `fileTree` می‌آید، مستقیم روی کلاس‌پس قرار می‌گیرد و هیچ
`exclude` وابستگی‌ای آن را برنمی‌دارد. نتیجه:

- اگر فقط کلاس‌های فروشنده بمانند، `Firebase Crashlytics` هنگام راه‌اندازی
  `NoSuchMethodError` می‌دهد، چون `OkHttpClient$Builder.callTimeout` از
  نسخهٔ ۳.۱۲ اضافه شده است.
- اگر okhttp از Maven اضافه شود، `checkProdDebugDuplicateClasses` روی همهٔ
  کلاس‌های `okhttp3.*` شکست می‌خورد.

راه‌حل نهایی: مرحلهٔ `Drop the okhttp bundled inside the vendored aars` در job
بیلد، کلاس‌های okhttp فروشنده را از داخل aar حذف می‌کند و
`com.squareup.okhttp3:okhttp:3.12.13` تنها نسخهٔ روی کلاس‌پس می‌شود.

دو نکته که این مرحله باید رعایت کند و در کد توضیح داده شده‌اند: کلاس
`okhttp3/logging/HttpLoggingInterceptorPrj` متعلق به خود پروژه است و
`com/rest/RestClient.java` آن را می‌سازد، پس حذف کل پکیج باعث
`NoClassDefFoundError` روی اولین درخواست شبکه می‌شد؛ و چون aar در فضای کاری
تغییر داده می‌شود، `app/build` باید پاک شود تا خروجی قدیمی دوباره merge نشود.
